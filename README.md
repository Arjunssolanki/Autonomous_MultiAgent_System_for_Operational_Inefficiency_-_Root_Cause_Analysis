# Autonomous Multi-Agent Operational Inefficiency & Root-Cause Analysis 

An enterprise-grade, production-ready Multi-Agent AI system designed to automate the business analysis lifecycle. The platform ingests complex operational problem statements, orchestrates specialized AI agents to isolate data anomalies, translates findings into strategic business requirements, and manages the execution lifecycle using advanced MLOps and cloud patterns.

## Technical Architecture Overview
- **Multi-Agent Orchestration Framework:** Utilizes the CrewAI state engine to manage sequential token hand-offs between a Senior Operations Data Analyst Agent and a Lead Business Systems Analyst Agent.
- **Advanced Inference Engine:** Powered by the production-tier Gemini 3.6 Flash architecture via Google AI Studio, protected against Anthropic-specific cache payload injections using low-level python monkey-patch overrides.
- **MLOps Tracking Infrastructure:** Full experiment tracking implemented via local MLflow server instances, logging pipeline execution durations, model metrics parameters, and textual run inputs.
- **Cloud Data Lake Storage Integration:** Automated storage pipelines using the boto3 client layer to pipe finalized markdown requirements documents directly into an AWS S3 data lake storage bucket.
- **Interactive UI Dashboard:** Built an interactive presentation workspace using Streamlit, featuring a quantitative simulation sandbox environment, active line chart data distributions, and dynamic file exporter buttons.

## How We Use MLflow in this Project
MLflow functions as our centralized experiment tracking and observability engine. In production AI systems, you cannot run model loops blindly without monitoring performance.
1. **Parameter Logging:** The system automatically logs execution configuration details, including the model identifier name and orchestration framework metadata tags.
2. **Performance Metrics Tracking:** A precision time module computes the exact system execution duration in seconds and logs it to track system latency across operational query variations.
3. **Artifact Archiving:** The script captures the raw text problem input alongside a localized copy of the finalized markdown report, storing them securely inside a structured run execution directory.

## How We Use AWS S3 in this Project
AWS S3 acts as our enterprise data lake layer, ensuring that the strategic outputs generated by the agents are persisted securely for long-term audit trails.
1. **Dynamic File Serializing:** When the analysis completes, the system generates a unique, timestamped string filename matching standard corporate schema standards.
2. **Decoupled Pipelining:** Using the boto3 SDK client layer, the application transmits the markdown requirements sheet as an independent text asset stream directly into the target bucket.
3. **Cross-Functional Accessibility:** By pushing files to the cloud data lake under the `operational_reports/` path prefix, downstream engineering systems (like Jira integrations or automated dev ticket systems) can consume the requirements without touching the frontend code.

## How to Set Up and Run the Project

### 1. Initialize Your Local Environment Setup
Clone the repository workspace into your local system and open the directory inside your terminal console:
```bash
python -m venv agent_ba_env
```

Activate the isolated virtual environment:
```bash
.\agent_ba_env\Scripts\Activate.ps1
```

Install the required framework package versions cleanly:
```bash
pip install -r requirements.txt
```

### 2. Configure Your System Credentials
Create a file named `.env` in the root folder workspace and establish your secure authorization strings:
```env
GROQ_API_KEY=your_groq_developer_key
GEMINI_API_KEY=your_google_ai_studio_key
MLFLOW_TRACKING_URI=http://127.0.0.1:5000
AWS_ACCESS_KEY_ID=your_aws_iam_access_key
AWS_SECRET_ACCESS_KEY=your_aws_iam_secret_key
AWS_DEFAULT_REGION=ap-south-1
S3_BUCKET_NAME=gentic-operational-analytics-lake
```

### 3. Initialize the Background MLflow Tracking Server
Open a dedicated terminal window panel inside your editor workspace, ensure your unique virtual environment is active, and boot up the tracking manager interface:
```bash
mlflow server --host 127.0.0.1 --port 5000
```
Keep this tracking terminal window running actively in the background.

### 4. Execute Core Agent Processing Logic via Terminal
To test raw agent loops directly inside your system command interface outside the dashboard layout, open a secondary shell panel and run:
```bash
python main.py
```
Type your complex operational problem statement text when prompted in the shell prompt to view the agents processing and printing real-time logs.

### 5. Launch the Interactive Presentation UI Dashboard
To boot up the complete visual workspace with input text blocks, sandboxed simulation sliders, interactive distribution line graphs, and asset exporting buttons, execute:
```bash
streamlit run app.py
```
This automatically compiles your frontend elements and launches the interface viewport window inside your default internet web browser layer.

## How to Verify Your Outputs Across Systems

### Evaluating MLflow Charts
Navigate your web browser address bar to `http://127.0.0.1:5000`. Select your experiment name in the sidebar menu to access execution summary lists. Click into individual run tracking rows to review logged parameters, latency duration trends, and download version-controlled report files.

### Verifying AWS S3 Data Storage
Log into your AWS Management Console dashboard, search for the S3 service, and click on your specific data lake storage container block. Navigate through the directory layers by entering the `operational_reports/` folder prefix path. Your files will be securely logged as timestamped documents, ready for downstream team integrations.
